При подключении к Windows VPS через удалённый рабочий стол (RDP) может появиться следующее сообщение:

> **Unable to connect**
>
> We couldn't connect to the remote PC because the user account has been locked due to too many sign in or password change attempts.
>
> Error code: **0xd07**

Оно означает, что подключение невозможно: учётная запись заблокирована из-за слишком большого числа попыток входа или смены пароля. Это защитный механизм Windows, часто срабатывающий на общедоступных Windows-серверах.

## Почему это происходит {#why-this-happens}

Windows автоматически временно блокирует учётные записи после нескольких неудачных попыток входа.

Во многих случаях это **не связано напрямую с вашими действиями**.

Автоматические боты постоянно сканируют общедоступные службы RDP и пытаются подобрать пароли на Windows-серверах, подключённых к интернету.

Распространённые причины:

- Неверные сохранённые учётные данные RDP
- Несколько неудачных попыток ввода пароля
- Смена пароля при сохранённых в кеше старых данных
- Автоматические попытки входа ботов, сканирующих порт `3389`
- Службы RDP, открытые для всего интернета

## Быстрое решение {#quick-solution}

### 1. Подождите и повторите попытку {#1-wait-and-try-again}

Время ожидания зависит от политики **Account lockout duration** на сервере. Значение `0` означает, что учётную запись должен разблокировать администратор; одного ожидания недостаточно. См. [документацию Microsoft о блокировке учётных записей](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/security-policy-settings/account-lockout-duration).

Прекратите повторные попытки подключения и перед следующей проверьте старые сохранённые учётные данные. Если у вас есть другая рабочая учётная запись администратора, используйте [консоль VNC](/ru/vps-management/enable-vnc-server), чтобы проверить локальную учётную запись и политику блокировки.

### 2. Проверьте имя пользователя и пароль {#2-verify-username-and-password}

Убедитесь, что используете:

- правильное имя пользователя;
- правильный пароль;
- правильную раскладку клавиатуры.

Если вы недавно сменили пароль, удалите старые сохранённые учётные данные.

### 3. Удалите сохранённые учётные данные RDP {#3-remove-saved-rdp-credentials}

Старые сохранённые данные — очень распространённая причина.

В Windows:

1. Откройте:
   ```text
   Control Panel → Credential Manager
   ```
2. Удалите старые учётные данные RDP для этого сервера.
3. Подключитесь снова и введите пароль вручную.

Если вы забыли пароль Administrator, см. [Как сбросить пароль Administrator в Windows](/ru/vps-management/reset-windows-admin-password).

## Рекомендуемые улучшения безопасности {#recommended-security-improvements}

Если порт RDP доступен всем в интернете, настоятельно рекомендуем усилить защиту.

### Ограничьте доступ RDP по IP {#restrict-rdp-access-by-ip}

Разрешите доступ RDP только с доверенных IP-адресов, используя:

- Брандмауэр Windows
- Внешние межсетевые экраны

### Измените стандартный порт RDP {#change-the-default-rdp-port}

Порт RDP по умолчанию:

```text
3389
```

Смена порта уменьшает количество автоматических сканирований и попыток подбора пароля.

### Включите Network Level Authentication (NLA) {#enable-network-level-authentication-nla}

NLA повышает безопасность RDP, требуя аутентификацию до запуска полного сеанса RDP.

Рекомендуется почти для всех установок Windows VPS и **включена в EDIS Global по умолчанию**.

### Используйте VPN вместо общедоступного RDP {#use-a-vpn-instead-of-public-rdp}

Для большей безопасности не открывайте RDP напрямую в интернет.

Рекомендуемые варианты:

- WireGuard
- Tailscale
- ZeroTier

Так доступ RDP будет проходить по защищённому частному туннелю.

## Затронутые версии Windows {#affected-windows-versions}

Проблема встречается во многих версиях Windows, включая:

- Windows 11
- Windows 10
- Windows Server 2025
- Windows Server 2022
- Windows Server 2019
- Windows Server 2016

## Всё ещё нужна помощь? {#still-need-help}

Если учётная запись остаётся заблокированной или сервер недоступен, обратитесь в поддержку и укажите:

- IP-адрес VPS;
- имя затронутого пользователя;
- приблизительное время возникновения проблемы.
