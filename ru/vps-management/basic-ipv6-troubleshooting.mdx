## Базовая диагностика IPv6 {#basic-ipv6-troubleshooting}

Большинство проблем IPv6 вызваны опечаткой, неверной длиной префикса, неправильным шлюзом локации или сетевым интерфейсом.

<Note>
  Каждый VPS получает собственный диапазон IPv6 размером `/64`, но это не отдельная маршрутизируемая подсеть `/64`. Настраивайте каждый выделенный IPv6-адрес VPS с **длиной префикса `/48`**, чтобы он мог обращаться к шлюзу локации.
</Note>

Используйте точный диапазон IPv6 и шлюз из приветственного письма или **Network Info** в [панели управления VPS](/ru/vps-management/ip-address-information).

## Проверьте настроенный адрес {#check-the-configured-address}

В Debian и других Linux-системах выполните:

```bash
ip -6 addr show
```

Пример вывода:

```text
eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 state UP qlen 1000
    inet6 2a03:f80:ed15:435a::1/48 scope global
```

Убедитесь, что:

- адрес входит в диапазон, выделенный этому VPS;
- используется длина префикса `/48`;
- нужный сетевой интерфейс включён;
- одновременно настроено не более 20 IPv6-адресов.

## Проверьте маршрут по умолчанию {#check-the-default-route}

Выполните:

```bash
ip -6 route show
```

Пример вывода:

```text
default via 2a03:f80:ed15::1 dev eth0
```

Убедитесь, что шлюз точно совпадает со шлюзом локации, указанным в панели VPS. Не вычисляйте и не угадывайте его по примеру.

## Проверьте внешнее подключение {#test-external-connectivity}

Используйте известный IPv6-ресурс:

```bash
ping -6 ipv6.google.com
mtr -6 -r ipv6.google.com
```

Если адрес, длина префикса `/48`, шлюз и интерфейс правильные, но IPv6 всё ещё не работает, обратитесь в [поддержку EDIS Global](https://www.edisglobal.com/contact) и приложите вывод команд.

<Warning>
  Ротация и случайная генерация IPv6-адресов, а также перебор адресов IPv6-прокси запрещены. Перед настройкой нескольких адресов прочитайте [Правила допустимого использования](/ru/getting-started/acceptable-use-policy).
</Warning>
