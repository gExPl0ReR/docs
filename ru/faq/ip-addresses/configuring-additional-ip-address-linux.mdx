## Настройка второго IP в Linux {#configure-a-secondary-ip-in-linux}

После заказа дополнительного IP для VPS он не добавляется в сетевые настройки сервера автоматически. Необходимо вручную настроить адрес в ОС или выполнить чистую переустановку для автоматической настройки IP. Обратите внимание: переустановка стирает все данные на KVM.

Ниже описано добавление второго IPv4 на VPS для основных дистрибутивов Linux.

## Debian/Ubuntu {#debian/ubuntu}

Debian и Ubuntu используют один способ настройки сети.

### 1. Отредактируйте файл сетевой конфигурации {#1-edit-the-network-configuration-file}

- Откройте терминал.
- Отредактируйте файл сетевых интерфейсов с помощью nano или другого редактора:

```shell
sudo nano /etc/network/interfaces
```

- Найдите запись своего сетевого интерфейса. Обычно она начинается с `iface`, например `iface eth0 inet static`.
- Для добавления IP вставьте следующую строку непосредственно под существующей конфигурацией:

```shell
up ip addr add [YOUR-SECOND-IP]/24 dev eth0

# NOTE: Replace [YOUR-SECOND-IP] with your additional IP address.
```

- Сохраните файл и выйдите: в nano нажмите `CTRL + X`, затем `Y` и `Enter`.

### 2. Перезапустите сетевую службу {#2-restart-the-networking-service}

```shell
sudo systemctl restart networking
```

## CentOS {#centos}

### 1. Перейдите в каталог сетевых скриптов {#1-navigate-to-the-network-scripts-directory}

```shell
cd /etc/sysconfig/network-scripts/
```

### 2. Создайте копию файла интерфейса {#2-create-a-clone-file-for-your-interface}

Если основной интерфейс — `eth0`, копия будет называться `eth0:0`.

```shell
sudo cp ifcfg-eth0 ifcfg-eth0:0
```

### 3. Измените конфигурацию копии {#3-edit-the-clone-configuration}

- Откройте новый файл конфигурации в редакторе:

```shell
sudo nano ifcfg-eth0:0
```

- Измените строку `DEVICE`:

```shell
DEVICE=eth0:0
```

- Укажите новый IP в строке `IPADDR`.
- Обязательно удалите или закомментируйте строку `UUID`.
- Сохраните файл и выйдите.

### 4. Перезапустите сетевую службу {#4-restart-the-network-service}

```shell
sudo systemctl restart network
```

---

**Примечание**: всегда проверяйте, что у вас есть разрешение на изменения, и сохраняйте резервные копии файлов конфигурации перед редактированием. Также рекомендуется заранее уведомлять затронутых пользователей: при перезапуске сетевых служб возможен краткий простой.
