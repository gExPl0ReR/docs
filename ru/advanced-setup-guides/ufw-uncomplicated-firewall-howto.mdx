UFW управляет межсетевым экраном внутри VPS с Linux. В этом руководстве рассматривается базовая настройка сервера Debian/Ubuntu с доступом по SSH.

<Warning>
  Включение UFW может прервать текущее SSH-соединение. Сначала разрешите доступ к фактическому порту SSH и держите [консоль VNC](/ru/vps-management/enable-vnc-server) доступной, пока не проверите новое подключение. Не сбрасывайте существующий межсетевой экран, не изучив защищаемые им службы и правила.
</Warning>

## Установка и проверка UFW {#install-and-inspect-ufw}

```bash
sudo apt update
sudo apt install ufw
sudo ufw status verbose
```

Если UFW уже включён, изучите текущие правила, прежде чем менять политики по умолчанию. Не управляйте одними и теми же правилами независимо через UFW, команды iptables и другой менеджер межсетевого экрана.

## Разрешите SSH перед включением UFW {#allow-ssh-before-enabling-ufw}

Для новой базовой конфигурации:

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
```

Замените `22` на фактический порт SSH. Добавьте правила для других необходимых служб **до** включения UFW. Например, веб-серверу обычно нужны:

```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
```

Затем включите межсетевой экран и проверьте его состояние:

```bash
sudo ufw enable
sudo ufw status verbose
```

Откройте **второе SSH-соединение** со своего компьютера и убедитесь, что оно работает, прежде чем закрывать исходный сеанс. Также проверьте необходимые порты приложений. Если VPS использует оба семейства адресов, проверьте правила IPv6 и IPv4.

В [руководстве UFW](https://manpages.ubuntu.com/manpages/jammy/man8/ufw.8.html) объясняется, почему важно разрешить SSH до активации.

## Ограничение доступа к службе доверенным адресом {#restrict-a-service-to-a-trusted-address}

Например, разрешите SSH только с известного адреса администратора:

```bash
sudo ufw allow proto tcp from 203.0.113.10 to any port 22
```

Замените приведённые для примера адрес и порт своими. Добавление этого правила не удаляет существующее правило, разрешающее доступ всем. Проверьте подключение с доверенного адреса, затем удалите более широкое правило, если хотите ограничить доступ. Учитывайте свой IPv6-адрес и возможные изменения домашнего или офисного IP-адреса.

## Просмотр и удаление правил {#review-and-remove-rules}

```bash
sudo ufw status numbered
```

Удалите правило по его номеру в списке, заменив `3` на нужный номер:

```bash
sudo ufw delete 3
```

После каждого удаления заново выводите список: номера правил меняются. Записи IPv4 и IPv6 могут быть отдельными.

## Восстановление доступа при блокировке соединения {#recover-from-a-blocked-connection}

Откройте консоль VNC, проверьте `sudo ufw status numbered` и добавьте или исправьте нужное правило доступа. Когда новое SSH-соединение заработает, удалите временные правила, которые больше не нужны.

Команда `sudo ufw disable` отключает фильтрацию UFW; используйте её только тогда, когда намеренно хотите временно отключить защиту. Команда `sudo ufw reset` удаляет настроенные правила и не является обычным способом устранения проблем с подключением.

Другие примеры приведены в статье [Базовая настройка UFW](/advanced-setup-guides/basic-ufw-debian-ubuntu).
