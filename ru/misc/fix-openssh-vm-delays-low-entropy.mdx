## Проверьте причину, прежде чем что-либо менять {#check-the-cause-before-changing-anything}

Медленное подключение по SSH не обязательно связано с энтропией. Различайте задержку при загрузке или создании ключей хоста и задержку при обычном входе. В Debian/Ubuntu проверьте:

```bash
sudo journalctl -b -u ssh --no-pager
sudo journalctl -b -k --no-pager
cat /sys/class/misc/hw_random/rng_available
```

Последний файл перечисляет драйверы RNG, доступные гостевой системе, если они есть. Само по себе отсутствие файла не доказывает, что именно это вызывает задержку SSH. Обращаясь в поддержку, приложите соответствующие временные метки и сообщения журналов.

## Как хост может предоставить устройство энтропии {#how-a-host-can-provide-an-entropy-device}

## Проблема: OpenSSH задерживает запуск системы {#problem-openssh-delays-system-startup}

Гостевые виртуальные машины (ВМ) могут испытывать задержки при запуске служб, например `OpenSSHd`, из-за недостаточной энтропии. Особенно это заметно при загрузке, когда службы блокируются в ожидании энтропии от `/dev/[u]random` или `getrandom()` в новых версиях Linux. Нехватка энтропии может увеличить время загрузки до одной минуты.

## Обзор решения {#solution-overview}

Энтропию можно передавать гостевым ВМ непосредственно с хоста, используя возможность QEMU предоставлять гостевой системе источник энтропии, например `/dev/urandom`. Это обеспечивает постоянное поступление энтропии без перегрузки хоста.

## Что такое энтропия? {#what-is-entropy}

В вычислительных системах энтропия — это **случайность**, которую операционная система собирает для криптографических и других операций, требующих случайных данных. Источниками могут быть аппаратные события: движения мыши, ввод с клавиатуры или системные прерывания.

Энтропия необходима для безопасности и непредсказуемости криптографических ключей, защищённой связи и генерации случайных чисел. В виртуальных средах физические события ввода ограничены, поэтому доступной энтропии может не хватать, что задерживает зависящие от неё операции.

Дополнительные источники энтропии, например VirtIO RNG, позволяют гостевым ВМ преодолеть эти ограничения и обеспечить стабильную работу служб, которым нужны случайные данные.

## Настройка {#implementation-steps}

### 1. Использование VirtIO RNG (генератора случайных чисел) {#1-use-virtio-rng-random-number-generator}

VirtIO позволяет эффективно передавать энтропию гостевой ВМ. Для его включения выполните следующие действия.

**Измените командную строку QEMU**
Добавьте следующие параметры к командной строке QEMU вашей ВМ:

```bash
-object rng-random,id=rng0,filename=/dev/urandom \
-device virtio-rng-pci,rng=rng0,max-bytes=1024,period=1000
```

*rng-random:* указывает источник энтропии (`/dev/urandom`) на хосте.

*virtio-rng-pci:* передаёт источник энтропии гостевой системе через интерфейс VirtIO.

*max-bytes* и *period*: ограничивают скорость передачи, чтобы поставщик энтропии не потреблял слишком много ресурсов CPU.

Описание источников RNG и виртуальных устройств есть в [документации по запуску QEMU](https://qemu-project.gitlab.io/qemu/system/invocation.html).

**Проверьте совместимость**

Гостевые системы с ядром Linux начиная с версии `2.6.32` могут автоматически использовать источник энтропии VirtIO после перезагрузки. Для более старых ядер и других ОС убедитесь, что драйвер VirtIO RNG поддерживается и включён.

***

### 2. Установка PRNG в гостевой системе (необязательно) {#2-install-a-prng-on-the-guest-optional}

Для старой системы с подтверждённой проблемой нехватки энтропии оцените возможность использования `haveged` по документации вашего дистрибутива. Не устанавливайте дополнительную службу энтропии только потому, что SSH кажется медленным. Если вы определили, что она подходит вашей системе:

```bash
sudo apt update
sudo apt install haveged
```

Запустите службу и включите её автоматический запуск:

```bash
sudo systemctl start haveged
sudo systemctl enable haveged
```

***

## Преимущества VirtIO RNG {#benefits-of-using-virtio-rng}

* Постоянная и быстрая передача энтропии с хоста.

* Отсутствие значительных задержек у гостевых служб, зависящих от генерации случайных чисел.

* Ограничение скорости предотвращает чрезмерное использование CPU хоста.

***

## Что следует учитывать {#considerations}

* Убедитесь, что на хосте достаточно энтропии для всех подключённых ВМ.

* Для задач с повышенными требованиями к безопасности оцените, соответствует ли источник `/dev/urandom` вашим требованиям.

***

## Заключение {#conclusion}

Настройка VirtIO RNG или использование PRNG, например `haveged`, может значительно сократить задержки запуска служб гостевой ВМ и повысить общую производительность системы.
