## Basic IPv6 troubleshooting

Most IPv6 connectivity problems are caused by a typo, an incorrect prefix length, the wrong location gateway, or the wrong network interface.

<Note>
  Each VPS receives its own `/64`-equivalent IPv6 allocation, but it is not a
  separately routed `/64`. Configure every assigned IPv6 address on the VPS
  with a **`/48` prefix length** so it can reach the location-specific gateway.
</Note>

Use the exact IPv6 allocation and gateway shown in your welcome email or under **Network Info** in the [VPS Management Portal](/vps-management/ip-address-information).

## Check the configured address

On Debian and other Linux systems, run:

```bash
ip -6 addr show
```

Example output:

```text
eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 state UP qlen 1000
    inet6 2a03:f80:ed15:435a::1/48 scope global
```

Confirm that:

- The address belongs to the allocation assigned to this VPS
- The address uses the `/48` prefix length
- The expected network interface is up
- No more than 20 IPv6 addresses are configured simultaneously

## Check the default route

Run:

```bash
ip -6 route show
```

Example output:

```text
default via 2a03:f80:ed15::1 dev eth0
```

Confirm that the gateway exactly matches the location-specific gateway shown in the VPS Management Portal. Do not derive or guess it from the example.

## Test external connectivity

Use a well-known IPv6 destination:

```bash
ping -6 ipv6.google.com
mtr -6 -r ipv6.google.com
```

If the address, `/48` prefix length, gateway, and interface are correct but IPv6 still does not work, contact [EDIS Global Support](https://www.edisglobal.com/contact) and include the command output.

<Warning>
  Rotating or randomly generated IPv6 addresses and IPv6 proxy address cycling
  are prohibited. Review the [Acceptable Use
  Policy](/getting-started/acceptable-use-policy) before configuring multiple
  addresses.
</Warning>
