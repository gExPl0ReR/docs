## Manual IP change instructions

Learn how to update your IP address without server reinstallation. Follow these step-by-step instructions to manually configure the network settings in Ubuntu.

<Warning>
  Use only the IP address, prefix length, gateway, and DNS settings assigned to your VPS in [Network Info](/vps-management/ip-address-information). The addresses in the screenshots are examples. Keep the VNC console open because changing an IP address interrupts SSH connections.
</Warning>

### Identify your network interface

Run these read-only commands in the VNC console:

```bash
ip -br -4 addr
ip -4 route show default
```

The interface after `dev` in the default route is the one to inspect. Its name might be `ens3`, `eth0`, or something else. The loopback interface `lo` is not your public network interface.

### Edit the Netplan configuration file

**Navigate to the Netplan directory**:

```bash
cd /etc/netplan/
```

Before editing, save a copy of the current Netplan configuration outside `/etc/netplan/`:

```bash
sudo cp -a /etc/netplan /root/netplan-before-ip-change
ls /etc/netplan/
```

**Open the configuration file** (e.g., `50-cloud-init.yaml`):

```bash
sudo nano /etc/netplan/50-cloud-init.yaml
```

Note: The filename might be different on your system (e.g., `01-network-manager-all.yaml`). Make sure to edit the correct file for your installation.

---

### Change the IP address

1. In the existing interface configuration, replace the old IPv4 address and prefix with the new values from **Network Info**.
2. Update the IPv4 gateway if it changed. Keep your existing IPv6 settings, interface matching, renderer, and any special routes unless the new network assignment requires a change.
3. Check the DNS settings. The resolver addresses below are examples; retain the resolvers appropriate for your VPS.

<Frame caption="Reconstructed Netplan example. 192.0.2.20/24 and 192.0.2.1 are documentation values, not settings to copy.">
  <img src="/images/ubuntu-netplan-ipv4.png" alt="Nano editor showing an IPv4 address with prefix and default route highlighted" />
</Frame>

The simplified example above is available as selectable text:

```yaml
network:
  version: 2
  ethernets:
    ens3:
      dhcp4: false
      addresses:
        - 192.0.2.20/24
      routes:
        - to: 0.0.0.0/0
          via: 192.0.2.1
      nameservers:
        addresses: [1.1.1.1, 1.0.0.1]
```

<Note>
  Edit the relevant values in your existing file; do not replace a more complete configuration with this simplified example. `/24` is only an example prefix. Older Netplan files may use `gateway4` instead of a default route; update the existing gateway setting rather than adding a duplicate. See the [Netplan configuration reference](https://netplan.readthedocs.io/en/stable/netplan-yaml/).
</Note>

### Configure multiple IPs (optional)

Only add addresses that EDIS Global has assigned to this VPS. List each address under the same interface's `addresses` key, keeping any existing IPv6 entries:

```yaml
addresses:
  - 192.0.2.20/24
  - 192.0.2.21/24
  - 192.0.2.22/24
```

These are documentation examples. Use your assigned addresses and prefix lengths, and preserve the indentation required by the surrounding file. See [Configure additional IP addresses](/faq/ip-addresses/configuring-additional-ip-address-linux) for the dedicated guide.

---

### Save configuration

1. Press `Ctrl + O` to write the file.
2. Press `Enter` to confirm the filename.
3. Press `Ctrl + X` to exit.

---

### Apply network changes

First validate the YAML, then try the configuration with a confirmation timeout:

```bash
sudo netplan generate
sudo netplan try --timeout 120
```

If validation reports an error, fix it before continuing. During the trial, test connectivity to the new IP from your computer and check the gateway and DNS from the VPS. Confirm in the VNC console only when the configuration works.

If you do not confirm, Netplan attempts to roll back. Keep VNC available and verify that both the running network and the files on disk are correct before rebooting; rollback has documented limitations. See [Netplan's `try` reference](https://netplan.readthedocs.io/en/stable/netplan-try/).

---

### Verify configuration

Check your new IP configuration using either command:

```bash
ip a
```

Or check a specific interface:

```bash
ip addr show dev ens3
```

(Replace `ens3` with your actual network interface name)
