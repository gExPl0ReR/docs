## Which option should I use?

| Situation | What to do |
| --- | --- |
| Linux or Windows is responding and you need a routine reboot. | **Restart from inside the operating system.** This lets it close applications and finish pending writes. |
| You need to restart from the dashboard. | Choose **Restart → Restart VPS** first. |
| Restart VPS did not help, or the VPS is stuck. | Choose **Restart → Power Cycle VPS** to power it off and back on. |
| The VPS is already stopped. | Click **Start**. |

<Warning>
  Both dashboard restart options interrupt the VPS and its services. They are not a substitute for a clean restart inside Linux or Windows: unsaved work or pending disk writes may be lost. Use the operating system's restart option whenever it is responding.
</Warning>

## Find the Restart menu

1. Sign in to the [VPS Management Portal](https://manage.edisglobal.com/clientarea.php).
2. Open **Services → My Services**, then select your VPS.
3. On the **Server Information** tab, find the server management panel.
4. Click the yellow **Restart** button to open the menu.

## Restart VPS

Choose **Restart → Restart VPS** to reset the virtual machine without a full power-off/power-on cycle.

The operating system reboots, but the process hosting the virtual machine and its VNC server stay running. If VNC is already enabled, you can follow the boot process in the console.

1. To watch the reboot, click **Start VNC** if VNC is disabled, then click **Open Console**. See the [VNC guide](/vps-management/enable-vnc-server).
2. Open **Restart** and choose **Restart VPS**.
3. Wait for the operating system to boot, then reconnect to SSH or Remote Desktop.

<Note>
  Keeping VNC available does **not** keep applications, SSH or Remote Desktop connected. Those services are interrupted while the operating system restarts. Older instructions may call this action **Reset VPS**; the current dashboard label is **Restart VPS**.
</Note>

## Power Cycle VPS

If **Restart VPS** does not resolve the problem, choose **Restart → Power Cycle VPS**.

This powers the virtual machine off and back on, starting a new virtual machine process. It also stops the existing VNC server. If you were using VNC, use **Start VNC** again and reopen **Open Console** after the power cycle.

Wait for the operating system and services to start before reconnecting. If the VPS still does not respond, [contact support](/getting-started/how-our-support-team-helps-you) with your VPS ID or IP address, the time of the problem and what you can see in the console.

## Restart gracefully from Linux or Windows

For routine maintenance, save your work and restart from inside the operating system.

### Linux

Connect through SSH or the console and run:

```bash
sudo shutdown -r now
```

If you are logged in as root, omit `sudo`. SSH disconnects during the reboot; reconnect after the server has started.

### Windows

Select **Start → Power → Restart** inside Windows. Your Remote Desktop session disconnects during the reboot; reconnect once Windows and Remote Desktop are ready.

## Start or stop a VPS

- **Start** turns on a stopped VPS.
- **Stop** powers off the VPS and leaves it off. If Linux or Windows is responding, shut it down from inside the operating system first: use `sudo shutdown -h now` on Linux or **Start → Power → Shut down** on Windows.

Restarting does not reinstall the operating system. [Reinstall OS](/vps-management/autoinstall-reinstall-install-vps-linux-windows) is a separate action that overwrites the existing system and data. Keep [backups](/getting-started/backups) outside the VPS.

Stopping a VPS does not cancel the service. To end the service, request cancellation in your client account.
