### Understanding CPU cores vs. CPU sockets in VPS environments

A VPS presents virtual CPUs to its operating system. The same number of vCPUs can be arranged as multiple virtual sockets or as multiple cores within one virtual socket. This guide shows where to change that presentation in the portal.
<CtaButton label="fast forward to guide" link="#3-adjusting-cpu-settings-in-vps-management-portal" />

### 1. CPU cores vs. CPU sockets: what's the difference?

* **CPU core**: A CPU core is an independent processing unit within a CPU. Modern CPUs can have multiple cores, allowing them to perform multiple tasks simultaneously. In a VPS environment, assigning multiple cores can increase the multitasking capability of a virtual machine.

* **CPU socket**: A CPU socket, often just referred to as a socket, is the physical slot on the computer's motherboard that holds the CPU. Each socket can hold one CPU chip, and that chip can contain one or more cores. When a VPS environment refers to 'sockets,' it often means virtual representations of these physical slots.

### 2. Virtualization capabilities

The guest operating system sees a **virtual CPU topology**, which does not reveal the physical socket layout of the host. For example, a four-vCPU VPS can be presented as:

| Presentation | Virtual sockets | Cores per socket | Total vCPUs |
| --- | ---: | ---: | ---: |
| Multiple sockets | 4 | 1 | **4** |
| Multiple cores | 1 | 4 | **4** |

This simplified example assumes one thread per core. Changing the presentation does **not** add vCPUs or upgrade the plan. See [libvirt's CPU topology documentation](https://libvirt.org/formatdomain.html#cpu-model-and-topology).

### 3. Adjusting CPU settings in VPS Management Portal

<Steps>
  <Step title="Open the VPS">
    In the [VPS Management Portal](https://manage.edisglobal.com/clientarea.php), go to **Services → My Services** and select the VPS.
  </Step>
  <Step title="Open System Configuration">
    On **Server Information**, click **System Configuration** in the **Server management** panel.
  </Step>
</Steps>

<Frame caption="Current portal control, highlighted for reference.">
  <img src="/images/portal-system-config-button-v2.png" alt="Server management panel with the System Configuration button highlighted" style={{ maxWidth: "540px", margin: "0 auto" }} />
</Frame>

<Steps>
  <Step title="Choose the CPU presentation">
    In **Configuration Details → CPU Settings**, find **CPU cores vs sockets**. Choose **multiple cores** or **multiple sockets**, according to the requirements of your operating system and software. This setting is relevant when the VPS has more than one vCPU.
  </Step>
  <Step title="Apply and power-cycle">
    Click **Apply**. Schedule the interruption, shut down the operating system cleanly, and power the VPS off and on as described in the [power-cycle guide](/vps-management/power-cycle-or-reboot-a-vps). The dialog explicitly requires a power cycle to activate changes.
  </Step>
</Steps>

<Frame caption="The CPU layout field is highlighted. Other example settings are not recommendations to change your boot mode or drivers.">
  <img src="/images/portal-cpu-layout.png" alt="Configuration Details showing CPU cores vs sockets set to multiple cores, Apply and the power-cycle notice" style={{ maxWidth: "580px", margin: "0 auto" }} />
</Frame>

After startup, verify the processor layout inside the guest. In Linux, use `lscpu`. For Windows, follow the CPU-check guide linked below.

### 4. When to change the settings

Use a layout supported by your operating system and applications. **Multiple cores** is useful where software supports fewer sockets than the VPS would otherwise expose.

<Note>
  Windows socket limits depend on the edition and version. The blanket claim that all Windows systems support only two sockets is incorrect. Consult [Microsoft's Windows Server limits](https://learn.microsoft.com/en-us/windows-server/get-started/locks-limits) and the documentation for your specific guest OS.
</Note>

Changing the virtual topology is not a guaranteed performance improvement. Check application requirements before changing it; ask support if you are unsure which presentation you need.
