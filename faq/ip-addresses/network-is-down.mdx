---
title: Network is down (Linux server)
description: "When your Linux VPS appears unreachable or the network seems down, connect via VNC and follow these steps to diagnose and restore network connectivity."
---

If SSH or an application is unreachable, first check [service status](https://status.edis.global) and whether the VPS is running. A failed ping alone does not prove the server is offline.

## Open the console

1. Open your VPS under **Services → My Services** in the [VPS Management Portal](https://manage.edisglobal.com/clientarea.php).
2. Click **Start VNC**, then **Open Console**.
3. Log in to Linux. The console remains useful even when networking inside the VPS is misconfigured.

See [VNC access](/vps-management/enable-vnc-server) for details.

## Check the interface and assigned settings

```bash
ip -br address
ip route
ip -6 route
```

Compare the interface, addresses, prefix lengths, and gateway with **Network Info** in the portal. Use your own assigned values, not values from a screenshot. For IPv6, follow the [IPv6 troubleshooting guide](/vps-management/basic-ipv6-troubleshooting).

## Separate routing from DNS problems

Replace `YOUR_GATEWAY` with the gateway shown in Network Info:

```bash
ping -c 4 YOUR_GATEWAY
ping -c 4 1.1.1.1
getent ahosts example.com
```

- An IP test working while name resolution fails points toward a resolver problem.
- A nonresponsive gateway may simply filter ICMP; compare multiple tests and actual application connectivity.
- If the interface lacks its assigned address or default route, inspect its persistent network configuration.

## Check the affected service and firewall

For SSH on Debian or Ubuntu:

```bash
sudo systemctl status ssh --no-pager
sudo journalctl -u ssh -n 50 --no-pager
sudo ss -lntp
```

On distributions such as RHEL, the service is usually named `sshd`. If socket activation is configured, also inspect `ssh.socket`. In the listener output, check the actual port and address on which SSH or your application is listening.

If you use UFW:

```bash
sudo ufw status verbose
```

Correct the specific rule that blocks the required service. See [Ports, firewalls and connectivity](/faq/ip-addresses/ports-firewalls-and-connectivity).

## Apply the right network fix

Network management varies by installation. Do not assume `systemctl restart networking` applies to every Linux system. For Ubuntu using Netplan, follow [Change IP on Ubuntu](/vps-management/manually-change-the-ip-address-in-ubuntu-versions-1804-to-2404), including backup, validation, and `netplan try`.

If Linux cannot boot, continue with the [rescue CD guide](/vps-management/linux-rescue-guide-and-troubleshoot).

## What to send support

Include the service identifier, source and destination IPs, time and timezone of the failure, exact error, and relevant command output. Remove passwords and private keys. Explain whether VNC works and whether the failure affects one service or all connectivity. Stop VNC after troubleshooting.
