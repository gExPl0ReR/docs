## Check where and how the connection fails

If your VPS or application cannot be reached from a particular country, ISP, mobile network or other connection, compare the affected connection with another available network. A difference between networks can help narrow down the problem, but does not by itself prove government filtering or an EDIS infrastructure fault.

Use the **current IP address**, especially if support has already changed it. Note your source country and ISP, the affected application or port, the exact error and the time of the test, preferably in UTC. The language you speak and the VPS location do not identify the network you are connecting from.

You can use the <a href="https://tools.keycdn.com/ping" target="_blank">KeyCDN ping tool</a> to compare ICMP reachability from other locations. A successful ping only confirms an ICMP response from that probe at that time. An open TCP port does not prove that SSH negotiation, RDP login, HTTPS downloads or sustained application traffic works from your network.

If an application connects and then stalls or disconnects, include that detail. For example, an SSH log showing `Connection established` followed by a key-exchange error is different from a TCP connection timeout. Repeated download stalls at a similar size are useful evidence, but do not establish the cause on their own.

## IP address changes

EDIS Global offers a free IP address change within 24 hours of purchase when the assigned IP works from other networks but cannot be reached from your network. Check the current eligibility and process in the IP-change guide.

<Note>
  A replacement IP or a different VPS location cannot guarantee access through every country or external network. If a replacement has already failed, provide the current and previous IPs to support so the case can be reviewed before considering further paid changes.
</Note>

Changing the assigned IP may require updating the network configuration inside the VPS. Follow the IP-change guide. Reinstalling erases data and is not a required first step for investigating regional connectivity.

## What support can review

Send support the current VPS IP, your source network, affected application, exact error, timestamps and any results already collected. Keep these in the same support conversation so you do not need to repeat completed tests. Do not send passwords, private keys or API tokens.

EDIS Global can review its infrastructure and service status. We cannot guarantee reachability through external networks, and our support does not provide traffic analysis, assistance to circumvent government filtering, or mitigation of such filtering. Self-service VPN documentation does not extend this support scope or guarantee connectivity from Russia or any other country.

If portal buttons, VNC activation, reboot or power controls also fail, report those errors separately. An ACTIVE or RUNNING status does not establish that management operations succeeded. See [Portal buttons not loading](/misc/portal-buttons-not-loading).

For interpreting network traces, see [Understanding packet loss in MTR and traceroute](/faq/ip-addresses/understanding-packet-loss-in-mtr-traceroute).
